# 08. «Антицензор» — PAC выборочной маршрутизации

Практическое воплощение манифеста (`07-prototypes/pid1-manifest.md`): **человек = PID 1 — правила маршрутизации пишет человек; корпорация = обслуга; маршрут по умолчанию — прямой.** PAC — стандарт 1996 года (Netscape Navigator 2.0): один локальный JavaScript-файл, читаемый глазами, отзываемый одним кликом. Никаких сервисов, DLL, расширений и телеметрии.

## Состав

| Файл | Назначение |
|---|---|
| `data/domains.txt` | Список маршрутов (формат описан в шапке файла) |
| `data/sources.d/*.txt` | Подключаемые файлы списков, подхватываются автоматически |
| `data/config.json` | Цепочка прокси (`proxy_chain`) и запасной маршрут (`fallback`) |
| `src/template.pac.js` | Шаблон скрипта с маркерами `/*@...@*/` |
| `src/build.py` | Сборщик: IDN→punycode, валидация, longest-match-карта, ASCII-гарантия, sha256 |
| `src/serve.py` | Локальная раздача с каноническим MIME |
| `tests/test_pac.py` | Оркестратор: сборка + структурные проверки + JS-векторы |
| `tests/pac.test.js` | 21 вектор + проверка `FindProxyForURLEx` (node) |
| `dist/anticenzor.pac` | Артефакт (генерируется, в репе — результат тестовой сборки) |

## Быстрый старт

```bash
python3 src/build.py        # соберёт dist/anticenzor.pac + напечатает sha256
python3 tests/test_pac.py   # сборка + проверки + векторы
python3 src/serve.py        # http://127.0.0.1:8080/anticenzor.pac
```

1. Впишите **свой** сервер в `data/config.json` → `proxy_chain`. Порядок = приоритет (движок пробует по очереди при сбое), последний элемент — запасной. Примеры серверов: локальный SOCKS5 (`ssh -D 1080`, userspace-WireGuard), HTTP-прокси (squid, tinyproxy), TLS-прокси (squid `https_port`, stunnel). PAC только выбирает маршрут; шифрование и аутентификация — задача самого сервера.
2. Свои домены — в `data/domains.txt` или отдельным файлом `data/sources.d/my-list.txt`.
3. Пересборка + тесты; URL обновляйте с кэш-бастером `?v=<sha12>` (печатает сборщик).

## Установка на Windows 10/11

- **Система** (Edge, Chrome и большинство приложений на WinInet): Параметры → Сеть и Интернет → Прокси → «Использовать сценарий настройки» → включить → URL: `http://127.0.0.1:8080/anticenzor.pac` (или ваш HTTPS-URL).
- **Реестр** (то же самое одной командой):
  `reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" /v AutoConfigURL /t REG_SZ /d "URL" /f`
- **Firefox** — собственный сетевой стек: Настройки → Параметры сети → «URL автоматической настройки сервиса прокси».
- **Точечный тест** в Chrome/Edge: `chrome --proxy-pac-url=http://127.0.0.1:8080/anticenzor.pac`
- **Edge** (собственный стек) качает PAC только по http/https/ftp — `file://` не годится (Microsoft TechCommunity, 27.04.2025).
- **Отключение**: выключить тумблер или `reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" /v AutoConfigURL /f`.

## Как работает

- Longest-match справа налево по меткам домена; исключения с `!` перебивают более общий ключ (побеждает самый длинный совпавший).
- Имена без точки (intranet/NetBIOS) и приватные литералы (RFC 1918, 127/8, 169.254/16, CGNAT 100.64/10, IPv6 ::1/fe80::/fc00::/7) — всегда DIRECT. Публичный литерал IPv4 можно занести в список — он проверяется картой как целый ключ.
- **`dnsResolve`/`isInNet`/`isResolvable`/`myIpAddress` сознательно не используются**: MDN прямо предупреждает — они ходят в DNS на каждый запрос и могут подвешивать браузер, `myIpAddress` часто возвращает 127.0.0.1; наш матчинг работает по имени хоста без единого DNS-вызова.
- IE 5.5+ кэширует результат PAC по домену — поэтому решения принимаются только по хосту, никогда по пути URL (заложено в дизайн).

## Совместимость типов возврата (верифицировано)

- `PROXY` / `SOCKS` / `DIRECT` — универсальны (Netscape 1996 → MDN).
- `HTTPS host:port` (TLS-прокси) — Chromium официально (проектный документ «Secure Web Proxy», пример `return "HTTPS secure-proxy.example.com:443"`), свежие Firefox (MDN). Для максимальной совместимости старых стеков первый элемент цепочки — `PROXY`.
- `SOCKS5`/`SOCKS4`, `HTTP` — свежие Firefox (MDN).
- MIME: `application/x-ns-proxy-autoconfig` (или `application/x-javascript-config`) — задан в `serve.py`.
- Тело PAC — чистый ASCII: UTF-8 PAC понимает только Firefox 66+; сборщик прерывает сборку при появлении не-ASCII.

## Безопасность

- PAC-URL вне локальной машины — только по HTTPS: раздача по голому HTTP позволяет MITM подменить скрипт и увести **весь** трафик браузера (предупреждение в литературе PAC с 2013 года).
- WPAD (автообнаружение) не используется и должен быть выключен: он угадывает URL скрипта по DHCP/DNS и перехватывается в чужих сетях. Только явный URL.
- Список и сервер — ваши; скрипт локален, не звонит домой, читается глазами за минуту.
- Кэш-бастер `?v=<sha12>` после каждой пересборки — движки подтянут свежую версию.
- Используйте на собственных устройствах и сетях; в чужих сетях действуют правила их владельца.
