# 01. Методология сбора и систематизации

## 1. Постановка

Задача: собрать как можно более полную информацию **за все годы существования Microsoft Windows** (20.11.1985 — 31.10.2026), категоризировать, классифицировать, сгруппировать и систематизировать её по всем пунктам: **с чем борются все пользователи за всё время** и **в чём систему активно продвигают** — и выдать результат **нумерованным списком между двумя полюсами с учётом релевантности**.

## 2. Анти-галлюцинационный протокол

1. Никакой факт (дата, число, цитата, название кампании) не попадал в отчёт до сетевой проверки.
2. Проверка выполнялась через поисковые индексы и прямое чтение страниц: Microsoft Learn / lifecycle / официальные блоги, StatCounter, Википедия (только для общепринятых исторических дат и событий с массой согласованных упоминаний), техническая и деловая пресса (The Verge, Ars Technica, ZDNet, Computerworld, BBC, Reuters, The Guardian, TechCrunch, PCMag, PC World, The Register, Neowin, gHacks, BleepingComputer, Windows Central/Latest и др.).
3. Каждому верифицированному факту присвоен тег `V-###` с URL в [SOURCES.md](SOURCES.md) и датой проверки 31.10.2026.
4. Всё, что проверить не удалось, **помечено `UNVERIFIED` и не участвует в рейтингах и выводах**. Полный список — в конце SOURCES.md.

## 4. Шесть эпох (группировка во времени)

- **I. 16-битная надстройка** — 1985–1993 (1.0, 2.0, 2.1x, 3.0, 3.1x)
- **II. Разделение 9x/NT** — 1993–2001 (95, 98, ME ‖ NT 3.1–4.0, 2000)
- **III. Консолидация XP** — 2001–2009 (XP, Server 2003, Vista)
- **IV. Семёрка и модернизация** — 2009–2015 (7, 8, 8.1, Server 2012/R2)
- **V. WaaS и десятка** — 2015–2021 (10, Server 2016–2022)
- **VI. AI-одиннадцать** — 2021–2026 (11, Server 2025, Copilot+)

Матрица «категория × эпоха» — в [03-eras.md](03-eras.md).

## 5. Шкала полярности (две крайности)

Каждая тема получает координату **от −10 до +10**:

- **−10 … −7** — полюс боли: пользователи десятилетиями/массово борются (иски, скрипты-обходы, утилиты возврата, отток, медиаволны).
- **−6 … −3** — систематическое раздражение, но терпимое.
- **−2 … +2** — гибрид: обещанное благо и реальная нагрузка одновременно.
- **+3 … +6** — активное продвижение без массовой обратной реакции.
- **+7 … +10** — полюс продвижения: центральные лозунги и витрины эпохи.

## 6. Критерии релевантности (формула ранжирования)

Ранг в главном списке = упорядочивание по интегральной оценке из трёх множителей (качественная шкала 1–5 каждый):

```
Релевантность ~ Длительность × Охват × Интенсивность реакции
```

- **Длительность**: сколько лет тема была в фокусе (BSOD — ~40 лет; GWX — 1 год).
- **Охват**: доля пользователей, которых тема касалась (обновления/реклама — все; Recall — подмножество).
- **Интенсивность реакции**: иски и класс-акции, всплеск утилит-обходов, коллективные протесты, публичные отступления Microsoft.

Пояснение калибровки: тема №1 «Обновления как принуждение» получает максимум по всем трём осям (40 лет с Windows Update 1998, охват 100%, реакции — от комикса про «не выключайте компьютер» до вердикта Голдстайн 2016 и DMA-принуждения 2024). Тема «Recall» — максимум интенсивности, но ограниченные длительность и охват, поэтому ниже. Оценки экспертные (помечено как аналитическое суждение, не факт).

## 7. Границы точности

- Даты retail-запусков версий — до дня там, где источник даёт день; иначе месяц/год.
- Оценки бюджетов кампаний — всегда «по сообщениям прессы», точные цифры Microsoft не публиковала.
- Доля рынка — StatCounter (одна из методик; не единственная).
- Внутренние мотивы решений Microsoft не реконструируются — фиксируются только публичные заявления и действия.
